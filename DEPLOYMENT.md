# TutorPlan static-site deployment

## Production structure

`output/` is the web root. Upload its **contents**, not the containing `output` directory. The web root must directly contain `index.html`, `404.html`, `robots.txt`, `sitemap.xml`, `sitemap-general-tutor.xml`, `tutor/`, and `regions/`.

The current public family is `general_tutor` only. Its 1,270 canonical URLs are in `sitemap-general-tutor.xml`. Other future page families must receive their own validated sitemap before being added to `sitemap.xml`.

## Pre-deployment check

Run from the repository root:

```powershell
python validate_predeploy.py
```

Upload only when it prints `"status": "PASS"`.

## URL and redirect policy

- Canonical host: `https://tutorplan.co.kr`
- Redirect `http` to `https` with a permanent redirect.
- Redirect `www.tutorplan.co.kr` to `tutorplan.co.kr` with a permanent redirect.
- General tutor canonical paths have no trailing slash because their canonical inventory uses that form.
- Directory paths (`/regions/…/`, `/contact/`, `/privacy/`, `/terms/`, `/tutoring/`) use trailing slashes.
- Do not use an SPA fallback. Unknown paths must serve `404.html` with HTTP 404.

## Static hosting options

### Vercel (GitHub-connected static deployment)

Use the project root as the Vercel Root Directory. The committed `output/` folder is the complete static artifact; this project must not be detected or deployed as the preserved `web/` Next.js project.

- Framework Preset: **Other** (`vercel.json` sets `framework` to `null`)
- Build Command: **empty / disabled** (`buildCommand: null`)
- Output Directory: `output`
- Install Command: not required

`vercel.json` provides a single pattern rewrite for every canonical `/tutor/...` URL. It serves the corresponding physical `index.html` without changing the browser URL. The pattern covers the 1,270 `general_tutor` pages and the preserved 123 regression sample URLs; it does not enumerate individual routes. Do not set Vercel `cleanUrls` or `trailingSlash`: this site intentionally uses slash-free tutor canonicals and trailing-slash directory canonicals such as `/regions/`.

There is no SPA fallback. Do not add a rewrite to `/index.html`; unknown paths must remain Vercel static 404 responses using `output/404.html`.

For custom domains, first add `tutorplan.co.kr` in **Project Settings → Domains** and complete the DNS verification Vercel shows. Add `www.tutorplan.co.kr` afterwards and set it to redirect permanently to `https://tutorplan.co.kr`, preserving path and query string. Vercel provisions HTTPS after domain verification; confirm both `http` and `www` end at the non-www HTTPS canonical without a redirect loop. This host-level redirect is intentionally configured in Vercel Domains, not in `vercel.json`.

`output/_redirects` and `output/_headers` are retained Cloudflare Pages artifacts. Vercel does not use them for production behavior; it uses the root `vercel.json`. They may remain versioned for a future Cloudflare workflow, but must not be treated as Vercel configuration.

Preferred release sequence: update data/content locally → run the Python generators → run `python validate_predeploy.py` and `python validate_vercel_static_config.py` → review the completed `output/` artifact → commit → push to GitHub → let Vercel deploy the static artifact. Do not run the content pipeline on Vercel for this project.

#### GitHub commit scope

Commit the Python generators and validators, `data/config/`, the small generated inventories needed for local verification, `review/` reports that are within GitHub's file-size limits, `output/`, `vercel.json`, `.gitignore`, and this deployment document. The current `output/` artifact is about 14 MB and is intentionally versioned because Vercel serves it directly.

Do not commit `.env`, `.vercel/`, Python caches, or `과외.xlsx`. The workbook is required only for a local regeneration and is not required by Vercel. Treat it as private source data; put it in a separately access-controlled repository only if there is explicit approval. Also keep the reproducible nationwide candidate and large review exports listed in `.gitignore` out of the deployment repository: several exceed GitHub's ordinary 100 MB single-file limit. This exclusion does not delete them from the local workspace.

### Cloudflare Pages

Use `output` as the publish directory, select **None / Static HTML** as the framework preset, and leave the build command empty. This site is already generated by Python; Pages must not run a Node.js build. Run `python prepare_cloudflare_pages.py` after the final Python content pipeline to write the publish-root `_redirects` and `_headers` files.

`_redirects` contains 1,270 static 200 rewrites from each trailing-slash-free general tutor canonical URL to its physical `index.html`. This keeps the canonical inventory URL directly serviceable despite the directory storage layout. Pages supports up to 2,000 static redirects, so the current inventory is within the limit. Do not add a catch-all SPA rewrite.

Configure HTTP-to-HTTPS in Cloudflare SSL/TLS settings. Configure `www.tutorplan.co.kr` to `https://tutorplan.co.kr` as a **Bulk Redirect** or Redirect Rule with status 301, subpath matching, and query-string preservation. Host-level redirects are not defined in `_redirects`. Add `tutorplan.co.kr` through the Pages Custom domains flow before creating any DNS record. For an apex domain, Cloudflare requires the domain zone and its nameservers on Cloudflare; add `www` only after the apex custom domain is active.

Pages serves `404.html` for missing static assets when no SPA fallback is configured. After deployment, verify the HTTP status is 404 rather than merely checking the page body. Cloudflare Pages serves Brotli/Gzip when possible; no pre-compressed files are needed.

### Apache / conventional FTP hosting

Upload the contents of `output/` to `public_html` or the configured document root. Enable HTTPS and apply host redirects at the virtual-host level. If `.htaccess` is permitted, use it only after checking host-specific rules:

```apache
RewriteEngine On
RewriteCond %{HTTPS} !=on [OR]
RewriteCond %{HTTP_HOST} ^www\.tutorplan\.co\.kr$ [NC]
RewriteRule ^ https://tutorplan.co.kr%{REQUEST_URI} [R=301,L]
ErrorDocument 404 /404.html
DirectoryIndex index.html
```

### Nginx

Use `output/` as `root`. A server block should redirect HTTP and `www` to the non-www HTTPS host, use `index index.html`, and return `/404.html` with status 404 for unknown paths. Do not use `try_files ... /index.html` as an SPA fallback.

```nginx
location / { try_files $uri $uri/ =404; }
error_page 404 /404.html;
location = /404.html { internal; }
```

## Caching and headers

- HTML and directory index pages: short cache, for example `Cache-Control: public, max-age=300`.
- `sitemap.xml`, `sitemap-general-tutor.xml`, `robots.txt`: short cache, for example five minutes.
- Versioned CSS, JS, images: long immutable cache when introduced.
- Enable gzip/Brotli at the hosting layer; do not commit compressed duplicates.

Recommended baseline headers: `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `X-Frame-Options: SAMEORIGIN` (or CSP `frame-ancestors 'self'`), a restrictive `Permissions-Policy`, and CSP introduced in report-only mode before enforcement.

## Deployment order

1. Run the pre-deployment validator.
2. Back up the existing web-root contents.
3. Upload the contents of `output/` to the web root.
4. Configure HTTPS, non-www redirect, and 404 behavior.
5. Confirm `/robots.txt`, `/sitemap.xml`, and several canonical URLs over HTTPS.
6. Add the HTTPS property to Search Console and submit `https://tutorplan.co.kr/sitemap.xml` only after the site is live.

## Rollback

Restore the previous web-root backup, purge the hosting cache if applicable, and rerun the validator against the intended artifact before attempting a corrected deployment.
